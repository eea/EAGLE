# Standards Crosswalk Briefing: EAGLE Object Model ↔ ISO 19144 Meta-Language

**Audience:** GIS Specialists, Earth Observation Analysts, Spatial Data Infrastructure Experts
**Focus:** Semantic alignment, nomenclature translation, and structural crosswalk

---

### 1. Conceptual Alignment: EAGLE vs. ISO 19144

Both EAGLE and ISO 19144 depart from traditional "flat" nomenclature legends (where a class code like "112" is an indivisible label) in favor of **deconstructed parametric land characterisation**. However, their structural representations differ:

| Concept                                      | EAGLE Conceptual Model                                                                          | ISO 19144 (LCML / LUML / LCHML)                                                                       | Implementation in Bridge                                                   |
| :------------------------------------------- | :---------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------- |
| **Land Parcel / Class**                | Land Characterisation Unit (LCU) / Class Code (e.g. `C112`)                                   | `LC_Class` under `LC_Legend`                                                                      | Modeled as canonical `LandUnit` (Pydantic / LinkML).                     |
| **Biophysical Surfaces**               | **Land Cover Components (LCC)** (e.g. `LCC-1_1_1` Sealed Surfaces, `LCC-2_1_1` Trees) | **ISO 19144-2 `LC_Element`** (`LC_BuiltUpSurface`, `LC_Tree`, `LC_Graminoid`, etc.)     | Mapped 1:1 via SSSOM exact/broad matches into `LC_Properties`.           |
| **Socio-Economic Function**            | **Land Use Attributes (LUA)** / HILUCS codes (e.g. `LUA-5_1` Residential)               | **ISO 19144-3 LUML** `LU_FunctionalType` (`LU_Residential`, `LU_Agriculture`)             | Stored in `LandUseAttribute` slot with functional relationship metadata. |
| **Biophysical & Management Modifiers** | **Land Characteristics (LCH)** (e.g. `LCH-5_1_4_5` Irrigation, Habitat, Soil sealing)   | **ISO Extensible Characteristics** (`LC_CultivatedAndManagedVegetationCharacteristics`, etc.) | Translated into `LC_Characteristics` blocks linked to parent strata.     |

### 2. Barcode Operators ↔ ISO Presence Logic

In the EAGLE matrix, relationships between components are encoded using integer **Bar Code Values (BCV)**. In ISO 19144-2, these are represented by **element presence types**:

| EAGLE BCV                         | Semantics                                         | ISO 19144-2 Presence Type                     | Semantic Rationale                                                                           |
| :-------------------------------- | :------------------------------------------------ | :-------------------------------------------- | :------------------------------------------------------------------------------------------- |
| **BCV 3**                   | Cumulative Mandatory (`AND`)                    | `Fixed`                                     | Mandatory component: surface element is compulsory for the class definition.                 |
| **BCV 1**                   | Optional / Typical occurrence                     | `Conditional` (or `Conditional Temporal`) | Permitted but not required across all spatial instances of the unit.                         |
| **BCV 2** / **BCV 5** | Disjunctive Mandatory (`EITHER-OR`) / Exclusive | `Exclusive`                                 | Disjunctive alternative: one of several elements must be present to the exclusion of others. |
| **BCV X**                   | Explicitly excluded                               | `Precluded`                                 | Explicit negative constraint (e.g., rice/hops precluded in general arable land).             |

---

### 3. Coverage Factors ↔ ISO Quantitative Cover Ranges

* **EAGLE Approach:** EAGLE matrices often aggregate coverage into discrete factor indices (e.g., factor `055` representing 30%–80% sealing; factor `075` representing >75% crop coverage).
* **ISO 19144 Approach:** Uses explicit numerical ranges via `<cover>` elements (`<CoverMin>` and `<CoverMax>` or paired relational `<cover>` tags).
* **The Bridge Crosswalk:**
  * **EAGLE ➔ ISO:** Reconstructs the quantitative threshold range from factor strings (e.g., `055` $\rightarrow$ `min: 30%, max: 80%`; `075` $\rightarrow$ `min: 75%, max: 100%`).
  * **ISO ➔ EAGLE:** Evaluates the `min`/`max` cover boundaries and derives the standardized EAGLE factor representation.

### 4. XML Relational Structure (LChS Compatibility)

The XML generated by the tool matches the official relational schema used by the FAO / ISO TC 211 **Land Characterisation System (LChS)**:

```
LC_Legend
├── LC_Class (class_id, class_map_code, class_name)
├── LC_HorizontalPatterns (horizontal_pattern_id, class_id)
├── LC_Strata (stratumID, HPID, presenceType: "Fixed")
├── LC_Properties (StratumID, BlockReference: "LC_BuiltUpSurface", elementPresenceType, cover)
└── LC_Characteristics (StratumID, CharacteristicReference, irrigationType, speciesName)
```

* **XPath Resilience:** The parser is namespace-agnostic and supports both relational multi-table structures and single-hierarchy XML exports.
* **Extensibility:** To map custom regional EAGLE codes to LCML descriptors, simply add a row to `src/mapping/eagle_iso_sssom.yaml`. No Python code changes are required.
